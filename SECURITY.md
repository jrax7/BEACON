# Security reporting

Do not post credentials, private target details, or exploitable security findings in public issues.

If the repository Security tab offers **Report a vulnerability**, use that private channel. If it is unavailable, arrange a private reporting channel with a maintainer before sharing sensitive details. This file alone does not enable GitHub private vulnerability reporting.

Only assess targets you own or are explicitly authorized to test. Do not scan a maintainer's hosted instance merely because its source is public.

Keep secrets and generated assessment data out of source control. If a real credential is disclosed, revoke or rotate it; deleting the current file is insufficient to remove copies or historical exposure.

This is an early source release without a declared supported-version policy or completed independent security audit. Security fixes and supported versions will be documented as releases mature.
