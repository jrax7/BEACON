# Security reporting

Do not post credentials, private target details, or exploitable security findings in public issues.

Before publication, the maintainer must enable GitHub private vulnerability reporting and verify that the repository Security tab offers "Report a vulnerability". Use that private channel once it is available. A reporting channel is not configured by this file alone.

Only assess targets you own or are explicitly authorized to test. Do not scan a maintainer's hosted instance merely because its source is public.

Keep secrets and generated assessment data out of source control. If a real credential is disclosed, revoke or rotate it; deleting the current file is insufficient to remove copies or historical exposure.

Security fixes and supported-version policy will be documented with the first public release. This candidate does not claim a completed independent security audit.
